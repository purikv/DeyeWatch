## Звідки беруться дані

```
 Інвертор Deye ──RS485/Modbus──▶ WiFi-стік Solarman ──Wi-Fi──▶ роутер ──▶ DeyeWatch
                                         │                                   │
                                         └──інтернет──▶ Deye Cloud ──API──────┘ (опційно, лише догрузка історії)
```

DeyeWatch підключається до WiFi-стіка **напряму в локальній мережі** по TCP-порту **8899**
протоколом **Solarman V5** — це обгортка над Modbus RTU:

- **Запит:** `0xA5`, довжина, control `0x4510`, лічильник, серійний номер стіка, далі
  frame type `0x02`, службові байти й Modbus-кадр (функція `0x03` — читання регістрів, CRC16), контрольна
  сума, `0x15`. Стік відповідає лише на запити зі своїм серійним номером.
- **Відповідь:** control `0x1510`; Modbus-кадр усередині.

За одне опитування читаються два блоки регістрів (`0x003B`, 54 шт. і `0x0096`, 45 шт.) — типово
раз на 10 секунд.

**Автопошук стіка:** програма надсилає UDP-рядок `WIFIKIT-214028-READ` на порт **48899** —
широкомовно та адресно кожному хосту підмережі /24 (широкомовні пакети часто не проходять крізь
ретранслятори Wi-Fi). Стік відповідає `IP,MAC,серійний номер`.

## Регістри інвертора

Карта регістрів — з файлу `deye_hybrid.yaml` проєкту
[StephanJoubert/home_assistant_solarman](https://github.com/StephanJoubert/home_assistant_solarman).

| Регістр | Показник | Одиниці / примітка |
|---|---|---|
| `0x003B` | Стан інвертора | 0 очікування, 1 самоперевірка, 2 працює, 3 аварія |
| `0x0046` / `0x0047` | Заряд / розряд батареї за день | ×0,1 кВт·год |
| `0x004C` / `0x004D` | Куплено / продано за день | ×0,1 кВт·год |
| `0x004F` | Частота мережі | ×0,01 Гц |
| `0x0054` | Споживання за день | ×0,1 кВт·год |
| `0x005A` / `0x005B` | Температура DC / AC | (x − 1000) × 0,1 °C |
| `0x006C` | Вироблено СЕС за день | ×0,1 кВт·год |
| `0x006D`–`0x0070` | Напруга й струм PV1, PV2 | ×0,1 |
| `0x0096` | **Напруга мережі** | ×0,1 В |
| `0x00A6` | Потужність на порту GEN (генератор) | Вт, зі знаком |
| `0x00A9` | Потужність мережі | Вт, + імпорт / − експорт |
| `0x00B2` | Потужність навантаження | Вт |
| `0x00B6` | Температура батареї | (x − 1000) × 0,1 °C |
| `0x00B7` | Напруга батареї | ×0,01 В |
| `0x00B8` | Заряд батареї (SOC) | % |
| `0x00BA` / `0x00BB` | Потужність PV1 / PV2 | Вт |
| `0x00BE` | Потужність батареї | Вт, + розряд / − заряд |
| `0x00C2` | Підключення до мережі | 0 off-grid, 1 on-grid |

## Визначення відключень

- **Світла немає**, якщо напруга мережі (`0x0096`) нижча за поріг (типово 170 В) у 2 опитуваннях
  поспіль; **світло є** — навпаки. Тому сповіщення приходить через ~10–20 секунд після події, а
  миттєві «блимання» ігноруються.
- Якщо програму запустили, а стан змінився, поки вона не працювала, відключення закривається
  останнім відомим моментом, а [хмара](#deye-cloud) потім уточнює справжній час.
- Після кожної догрузки з хмари журнал відключень перебудовується за всіма хвилинними записами;
  відключення коротші за 2 хвилини відкидаються, а близькі (з перервою < 2 хв) — склеюються.
- **Генератор** вважається запущеним, коли потужність на порту GEN (`0x00A6`) перевищує поріг
  (типово 30 Вт) у 2 опитуваннях поспіль.

## Розрахунки

| Показник | Формула |
|---|---|
| Батареї вистачить | (заряд − мінімальний заряд) × ємність ÷ середня потужність розряду за 10 хв |
| Самозабезпечення | 1 − куплено з мережі ÷ спожито |
| Повні цикли батареї | сумарний розряд ÷ ємність |
| Енергія генератора | сума хвилинних середніх потужностей на GEN |
| Поза нормою | хвилини, коли мінімум або максимум напруги виходив за межі норми |

## Зберігання даних

База SQLite `history.sqlite3` у теці налаштувань:

| Таблиця | Вміст |
|---|---|
| `samples` | Хвилинні записи: стан мережі, напруга (сер./мін./макс.), частота, потужності мережі, навантаження, PV, батареї й генератора, заряд, температури |
| `daily` | Енергія по днях (лічильники інвертора або статистика станції з хмари) |
| `outages` | Журнал відключень (початок, кінець) |
| `events` | Події: напруга поза нормою, втрата/відновлення зв'язку, генератор, синхронізації |
| `outbox` | Черга Telegram-повідомлень, які ще не вдалося надіслати |
| `kv` | Службові значення (токен хмари, стан тощо) |

Хвилинні записи зберігаються 365 днів (налаштовується), решта — без обмеження. Рік історії ≈ 30 МБ.

## Deye Cloud

Використовується офіційний [Deye Cloud OpenAPI](https://developer.deyecloud.com):

1. `POST /v1.0/account/token` — токен за App ID, App Secret, email і SHA-256 пароля (діє ~60 днів).
2. `POST /v1.0/station/listWithDevice` — станція й серійний номер інвертора.
3. `POST /v1.0/device/measurePoints` — назви доступних показників; програма сама підбирає потрібні
   (напруга, частота, потужності, заряд).
4. `POST /v1.0/device/historyRaw` — сирі записи (крок ~5 хв) для кожного проміжку без локальних даних;
   API віддає не більше 5 діб і 5 показників за запит, тож запити діляться на частини.
5. `POST /v1.0/station/history` — енергія по днях (до 30 днів за запит).

## Приватність і безпека

- Програма не має власного сервера, аналітики чи телеметрії.
- Мережеві з'єднання: WiFi-стік у локальній мережі; `api.telegram.org` — лише якщо ввімкнено Telegram;
  сервер Deye Cloud — лише якщо ввімкнено хмару.
- Токен Telegram, App Secret і хеш пароля Deye Cloud зберігаються у файлі налаштувань у вашому профілі
  користувача. Пароль Deye Cloud у відкритому вигляді не зберігається.
- Один екземпляр програми на користувача (файл блокування в теці налаштувань).
